# 日报发送前语义润色规则

本文定义手动 QQ 回复的最后一步。`reports/YYYY-MM-DD.qq.md` 和 `read-report` 返回的 `content`/`messages` 是事实底稿，Hermes 必须先润色，再交给当前入站 QQ 会话发送。

## 目标

把 Markdown 日报转换成手机端易读的中文纯文本，同时保留日报的事实、层级和顺序。润色是表达层处理，不是重新写一份摘要，也不是重新生成日报。

## 固定流程

1. 只处理本次 `report --json` 返回的 `qq_report_path` 对应内容，不读取旧日报，不按日期猜文件名，不重新执行 `report`。
2. 以 `messages` 为分段边界逐段润色；保留每段的日报日期和“第 x/y 部分”，不要把多段合并成一条，也不要提前发送原始分段。
3. 将“今日日报已生成，以下是完整日报正文：”拼接到第一段润色结果，不单独发送提示消息。
4. 按润色后的消息顺序发送。润色导致消息超限时，在最近的二级/三级标题或完整条目之间重新拆分；不能截断句子、链接、代码行或状态说明。
5. 最后一段保留“日报发送完成。”；只有所有润色后的分段发送成功，才能向用户表示日报已发送完成。

## 允许的表达调整

- 去掉 `#`、`##`、`###`、`**`、`*`、反引号、引用符和三反引号围栏。
- 标题保留为单独一行的普通文本；列表改成 `•` 或普通换行项目；不要把所有章节挤成一段。
- Markdown 链接转换为“来源：标题（URL）”或“标题：URL”。URL 必须逐字保留，不能缩短、改写、转义或删除。
- 翻译说明性英文、状态标签和连接词，使中文自然。`partial` 可以写为“部分完成（partial）”，其他机器状态也应保留原状态词，避免丢失可审计信息。
- 调整中文语序、标点、空格和重复的连接词。可以把“项目定位”“为什么重要”等固定英文提示改成自然中文。
- 代码示例去掉围栏后原样保留代码行，可在前面写“代码：”；不能执行、翻译、格式化或改写代码。

## 必须保持的内容

- 日期、时间、数字、版本号、排名、数量和状态值。
- 一级/二级/三级章节顺序、每个项目/新闻条目的顺序和条目数量。
- GitHub、Bilibili、YouTube、MCP 等产品或协议名，仓库名、账号名、专有名词和 URL。
- GitHub 热点、新闻、B站视频、B站动态、YouTube 视频等原有板块。
- `partial`、`network_error`、`empty` 等采集状态及其原因；失败不能润色成成功，缺少来源不能补造来源。
- 原日报中的重点提示、来源标题和证据链接。

## 禁止行为

- 不得直接发送 `.qq.md` 原文、JSON、Markdown 代码块或只发送正文开头。
- 重新总结、压缩成“几条重点”、合并/拆散条目、调换章节顺序或省略创作者动态。
- 删除来源链接、把链接改成不可点击文本、翻译 URL/仓库名/代码标识符。
- 擅自补充原日报没有的事实、结论、情绪或推荐；不能把不确定内容写成确定事实。
- 把任何文件路径、执行摘要、错误堆栈或内部工具输出混入日报正文。

## 输出自检

发送前逐段检查以下条件：

- 不含三反引号、`[标题](URL)`、连续 Markdown 星号或标题井号。
- 标题、列表、来源和正文仍然分层清楚，手机端不出现整段代码块样式。
- 所有原始 URL 仍存在且顺序正确；数字、日期、状态和条目没有变化。
- 分段日期、序号、顺序和完成标记完整；总长度符合当前 QQ Adapter 限制。
- 失败时只报告具体阶段、失败段序号和 `qq_report_path`，不声称“日报已发送”。

## 示例

原始 Markdown：

```text
## AI 新闻

### New Agent SDK

**Why it matters**: partial result.

[阅读原文](https://example.com/sdk)
```

允许的手机纯文本：

```text
AI 新闻

New Agent SDK

为什么重要：部分完成（partial）。
来源：阅读原文（https://example.com/sdk）
```

示例只移除 Markdown 外观并翻译说明性文字；没有删除状态或来源，也没有增加原文之外的结论。
